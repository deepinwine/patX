# CN 专利审查事件后台提醒设计

## 1. 背景与目标

patX 已具备 CNIPA 审查信息同步、OA 记录、期限规则和同步状态表。本次调整不再以下载审查意见正文为目标，而是通过已导入的中国专利申请号，后台获取最新官方审查事件的类型与日期，并在发现新事件时创建 OA 记录和提醒用户。

首期仅支持 CN 案件，不下载或保存通知书正文。

## 2. 范围

### 2.1 包含内容

- 使用专利主档中的中国申请号查询官方审查事件元数据。
- 按 USPTO Global Dossier、EPO Global Dossier、CNIPA 的顺序降级查询。
- 识别官方发文的类型与官方日期。
- 自动创建 OA 记录并避免重复创建。
- 在 patX 启动后和运行期间执行后台检查。
- 仅在发现新事件、数据冲突或需要用户登录时提醒用户。
- 保留手动检查选中案件和全部 CN 案件的入口。

### 2.2 不包含内容

- 不下载、预览或保存审查意见正文。
- 不支持 US、EP、JP、KR 等非 CN 案件。
- 不自动填写密码，不自动处理验证码。
- 不因授权或驳回事件直接修改专利主档状态。
- 不根据事件日期自动确认答复期限；现有期限规则仍作为建议值使用。

## 3. 数据源与降级顺序

### 3.1 USPTO Global Dossier

USPTO Global Dossier 是首选数据源。查询只读取 CN 案卷中的文档清单元数据，包括文档标题、官方日期、文档代码和远端标识，不请求文档正文。

该数据源不依赖 USPTO Open Data Portal API Key。实现应使用独立 Provider，并将网页结构或接口变化映射为明确的错误码，不能将空响应解释为“没有新事件”。

### 3.2 EPO Global Dossier

当 USPTO 查询超时、限流、页面结构变化或服务不可用时，自动使用 EPO Global Dossier。EPO 仅作为同一 CNIPA 案卷元数据的兜底来源。

如果 USPTO 与 EPO 对同一事件返回不同日期或不同类型，停止自动入库并标记为“待人工确认”。

### 3.3 CNIPA

当 USPTO 与 EPO 均无法返回可验证的结果时，将案件标记为“需要 CNIPA 验证”。后台任务不得自动弹出登录窗口；用户点击“登录 CNIPA”后，patX 才打开可见浏览器。

CNIPA 使用独立的持久化浏览器目录，保存 Cookie、`localStorage` 登录令牌和站点会话。后续启动自动复用该登录态。服务器令牌过期后再次提示用户登录。patX 不读取或保存密码，也不自动处理验证码。

## 4. 号码处理

- 只处理可规范化为 CN 申请号的案件。
- 支持带或不带 `CN` 前缀、带或不带校验位分隔点的输入。
- 查询前统一生成数据源所需的申请号形式。
- 无法确定校验位或申请号格式错误时，不猜测、不查询，记录“申请号无法识别”。
- 只有公开号而没有申请号时，可以复用现有 EPO OPS 解析能力；解析失败时要求用户补录申请号。

## 5. 事件筛选与分类

### 5.1 筛选规则

- 只处理官方发文方向的记录。
- Global Dossier 中只接受标题标记为 `ORIGINAL` 的记录。
- 忽略 `TRANSLATED` 记录，避免原文与机译记录重复入库。
- 忽略申请人提交的意见陈述、权利要求修改、说明书修改和其他申请文件。
- 缺少可解析官方日期的记录不得自动创建 OA。

### 5.2 统一事件类型

| 统一类型 | 中文显示 | 典型来源标题或代码 |
| --- | --- | --- |
| `OFFICE_ACTION_FIRST` | 第一次审查意见 | First notice of examination opinions、第一次审查意见通知书、`210401-CN` |
| `OFFICE_ACTION_SECOND` | 第二次审查意见 | Second notice of examination opinions、第二次审查意见通知书 |
| `OFFICE_ACTION_NTH` | 第 N 次审查意见 | Third/Fourth/Nth notice、第三次及后续审查意见通知书 |
| `REJECTION_DECISION` | 最终决定／驳回决定 | Decision to reject、驳回决定、明确的 Final rejection |
| `GRANT_NOTICE` | 授权通知 | Notification to grant patent right、办理登记手续通知书、授权通知 |
| `CORRECTION_NOTICE` | 补正通知 | Notification to make rectification、补正通知书 |
| `OTHER_OFFICIAL` | 其他官方通知 | 无法归入上述类型的官方发文 |

`Final` 不计入第几次审查意见。只有来源明确表示最终驳回或驳回决定时，才归入 `REJECTION_DECISION`。模糊标题进入人工确认，不自动猜测。

分类优先级为：稳定文档代码、规范化标题规则、保守兜底。代码和标题冲突时进入人工确认。

## 6. 数据模型与去重

### 6.1 最小元数据

系统只保存完成提醒和去重所需的元数据：

- 管辖地：`CN`
- 申请号
- 事件类型
- 官方日期
- 数据源：`uspto_global_dossier`、`epo_global_dossier` 或 `cnipa`
- 远端文档标识或稳定指纹
- 首次发现时间与最后检查时间
- 原始标题和文档代码（仅用于审计与分类排错）

不保存正文、下载地址或本地文档路径。

### 6.2 去重规则

优先使用数据源提供的远端文档标识。没有稳定远端标识时，以“管辖地＋申请号＋统一事件类型＋官方日期＋规范化原始标题”生成指纹。

同一事件从 USPTO 和 EPO 两个来源出现时，合并为一条 OA 记录，保留来源轨迹，不重复提醒。

### 6.3 OA 记录合并

- 新事件：自动创建 OA 记录，填写类型、发文日、来源、远端标识和 `sync_flag=web_new`。
- 已有相同类型、相同日期的记录：只刷新最后检查时间。
- 已有相同类型但本地日期为空：补入官方日期。
- 已有相同类型但日期不同：不覆盖本地日期，标记日期冲突。
- 不修改人工填写的处理人、撰写人、摘要、备注、答复日和人工期限。
- 授权或驳回事件只创建提醒记录，不自动修改专利主档状态。

## 7. 后台调度

- patX 启动约 30 秒后执行一次到期案件检查。
- 软件运行期间每 30 分钟检查调度队列。
- 每件 CN 案件默认每天查询一次。
- 设置中提供 1 天、3 天和 7 天查询间隔。
- 同一时间只运行一个同步批次，案件按顺序查询，不并发轰炸远端服务。
- 已放弃、失效、撤回、视撤或终止案件不进入后台队列。
- 授权案件默认不继续查询；用户可通过手动入口选择“包含已授权案件”。
- 网络失败、限流或临时错误不生成事件，下次调度自动重试。

## 8. 提醒与交互

后台检查默认静默运行，不显示进度窗口。

发现新事件时：

- 自动刷新 OA 列表并突出显示新记录。
- 显示桌面通知，内容包含案件编号或申请号、事件类型和官方日期。
- 点击通知后打开对应案件或 OA 记录。
- 一个批次发现多件新事件时显示汇总通知，用户可打开结果列表查看详情。

没有新事件时不显示通知。数据冲突显示“待人工确认”提醒。需要 CNIPA 登录时只显示提示和“登录 CNIPA”按钮，不在后台自动打开浏览器。

手动同步继续使用进度对话框，显示当前数据源、已检查数量、新事件数量、冲突数量和失败数量。

## 9. 错误处理

- 空响应、HTML 拦截页和非预期响应结构均视为临时错误或页面结构变化，不能视为无事件。
- 单个案件号码错误只影响该案件，不终止整个批次。
- 数据源整体不可用、限流或页面结构变化时停止当前数据源，进入下一数据源。
- 三个数据源均失败时记录失败原因，不修改 OA 数据。
- USPTO 与 EPO 结果冲突时保存诊断元数据并等待人工确认。
- 日志不得包含 Cookie、访问令牌、密码或 API Secret。

## 10. 安全与隐私

- 所有业务数据和同步状态继续保存在本地 SQLite 数据库。
- CNIPA 登录态只保存在 patX 专用浏览器 Profile 中。
- 不上传本地交底书、OA 文件或其他用户文件。
- 不自动填写登录凭据，不绕过验证码和站点安全验证。
- 后台查询遵循单线程、低频率和可配置间隔。

## 11. 测试策略

### 11.1 Python Provider 测试

- 使用固定响应样本测试 USPTO 与 EPO 文档清单解析。
- 测试 `ORIGINAL` 保留、`TRANSLATED` 排除和申请人文件排除。
- 测试 First、Second、Nth、Final/Rejection、Granted、Correction 的分类。
- 测试代码与标题冲突进入人工确认。
- 测试空响应、限流、HTML 拦截和页面结构变化。
- 测试三层数据源降级顺序。

### 11.2 C++ 合并规则测试

- 测试新事件自动创建 OA。
- 测试相同事件不重复创建或重复提醒。
- 测试空日期补入、日期冲突保护和人工字段不被覆盖。
- 测试授权与驳回事件不自动修改专利主档状态。
- 测试只选择到期的 CN 案件进入后台队列。

### 11.3 调度与界面测试

- 测试启动延迟、30 分钟调度和 1/3/7 天配置。
- 测试后台无变化时保持安静。
- 测试新事件、冲突和登录失效分别产生正确提醒。
- 测试点击提醒打开对应案件。

## 12. 验收标准

以 `CN202510469601.5` 为验证样例时，patX 能在不下载正文的情况下识别 `2026-05-23` 的第一次审查意见，创建且仅创建一条“第一次审查意见”OA 记录，并在首次发现时提醒用户。

重复检查不产生重复 OA 或重复提醒。USPTO 不可用时可自动通过 EPO 取得等价元数据；两者均不可用时提示使用已持久化登录态的 CNIPA 验证。
